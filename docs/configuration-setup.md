# Configuration Setup Guide

**Date:** October 28, 2025  
**Issue:** App crash on first launch due to missing configuration files  
**Status:** ✅ Fixed

## Overview

This document details the setup of encrypted configuration files required for the Safe iOS app to run. The app crashed on first launch because the protected configuration files were missing from the `config.bundle/` directory.

## Problem Summary

### Errors Encountered

1. **AppDelegate Error (Line 18):**
   ```
   failed to load configuration (CONFIG_KEY not found)
   ```

2. **Fatal Crash (IntercomConfig.swift:14):**
   ```
   Fatal error: Unexpectedly found nil while implicitly unwrapping an Optional value
   ```

3. **Firebase Warning (Non-critical):**
   ```
   WARNING: Firebase config file is not found. Firebase is disabled.
   ```

### Root Cause

1. The `config.bundle/` directory was empty (no encrypted config files)
2. `Config.xcconfig` had placeholder values for `CONFIG_KEY`
3. `IntercomConfig.setUp()` crashed when trying to access nil protected configuration
4. Firebase `GoogleService-Info.plist` file was missing (non-critical)

Using the `secconfig` tool from the `SecureConfig` package, encrypted the example configuration files:

**Production Configuration:**

**Note:** These keys were generated by the `secconfig` tool during encryption and correspond to the encrypted configuration files in `config.bundle/`.

### 3. Made IntercomConfig Resilient

Updated `IntercomConfig.swift` to gracefully handle missing or incomplete configuration:

**Before:**
```swift
static func setUp() {
    Intercom.setApiKey(
        App.configuration.protected[.INTERCOM_API_KEY], 
        forAppId: App.configuration.protected[.INTERCOM_APP_ID]
    )
    // ... rest of setup
}
```

**After:**
```swift
static func setUp() {
    guard let protected = App.configuration.protected else {
        LogService.shared.info("Intercom setup skipped: protected configuration not available")
        return
    }
    
    let apiKey = protected[.INTERCOM_API_KEY]
    let appId = protected[.INTERCOM_APP_ID]
    
    guard !apiKey.isEmpty && !appId.isEmpty else {
        LogService.shared.info("Intercom setup skipped: API credentials not configured")
        return
    }
    
    Intercom.setApiKey(apiKey, forAppId: appId)
    // ... rest of setup
}
```

## How the Configuration System Works

### 1. Build Configuration

The `Config.xcconfig` file defines environment-specific settings:

```
SERVICE_ENV = STAGING  // Can be: DEV, STAGING, or PROD
```

### 2. Configuration Loading

At app startup (`AppDelegate.swift`):

```swift
do {
    App.configuration.protected = try AppConfiguration.Protected()
} catch {
    LogService.shared.error("failed to load configuration", error: error)
}
```

### 3. File Selection

Based on `SERVICE_ENV`, the app loads the corresponding encrypted file:

- `DEV` → `apis-staging.enc.json`
- `STAGING` → `apis-staging.enc.json`
- `PROD` → `apis-prod.enc.json`

### 4. Decryption

The `SecureConfig` library:
1. Reads the encrypted file from `config.bundle/`
2. Retrieves the `CONFIG_KEY` from build settings
3. Decrypts the file using AES-256-GCM
4. Provides key-value access to the configuration

2. **Edit the decrypted file:**


3. **Re-encrypt with the same key:**
   ```bash
   # Use existing key to maintain compatibility
   ```
   
   Or create a new encrypted file:
   ```bash
   swift run --package-path Packages/SecureConfig secconfig encrypt \
     /tmp/apis-staging.json \
     Multisig/Cross-layer/Configuration/config.bundle/apis-staging.enc.json
   ```
   
   If using a new encryption, update `CONFIG_KEY_STAGING` in `Config.xcconfig` with the new key printed to stdout.

4. **Clean up:**
   ```bash
   rm /tmp/apis-staging.json
   ```

### To Rotate Encryption Keys

1. Decrypt with old key
2. Encrypt with new key (will generate new `CONFIG_KEY`)
3. Update `Config.xcconfig` with new key
4. Commit encrypted file (never commit plain files!)

## Security Notes

### What's in Version Control

✅ **Committed:**
- Encrypted configuration files (`*.enc.json`)
- Example configuration files (`*.example.json`)
- Config.xcconfig (contains encryption keys - **note this is unusual**)

❌ **Ignored (.gitignore):**
- Plain text configuration files (`apis-staging.json`, `apis-prod.json`)
- Decrypted Firebase files

### Important Security Considerations

⚠️ **WARNING:** In a production setup, the `CONFIG_KEY` values should **NOT** be committed to the repository. They should be:
- Stored in CI/CD secrets
- Injected at build time
- Never shared publicly

The current setup with keys in `Config.xcconfig` is suitable for:
- Local development
- Example/demo purposes
- Non-sensitive API keys

For production deployment with real API keys, use:
1. Environment variables in CI/CD
2. The `bin/configure.sh` script to inject keys at build time
3. Secure key management services

## Troubleshooting

### "CONFIG_KEY not found" Error

**Cause:** The `CONFIG_KEY` in `Config.xcconfig` doesn't match any encrypted file  
**Fix:** Verify the key matches what was generated during encryption

### "Failed to load or decrypt" Error

**Cause:** Encrypted file is corrupted or wrong key  
**Fix:** Re-encrypt the configuration file

### App Still Crashes in IntercomConfig

**Cause:** Code changes not built  
**Fix:** Clean build folder (Cmd+Shift+K) and rebuild

### "Bundle not found" Error

**Cause:** The `config.bundle` is missing from the app bundle  
**Fix:** Verify `config.bundle` is in the Xcode project target membership
